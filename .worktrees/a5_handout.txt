Mixture of experts
Though we would like to train larger models, this comes with the tradeoff of costing more compute.
Sparsely activated models allow us to increase parameter count while keeping expert compute per token
fixed, apart from routing overhead. In this problem, we will explore an incredibly primitive MoE in
the context of our d8. Note: Due to our suboptimal implementation, we will not achieve identical
run throughput. In principle, this is possible with proper performance optimizations that we did not
implement, so track FLOPs instead of end-to-end runtime (as ML researchers, we can heed this reminder).

Replace each MLP with four full-size SwiGLU experts, activating one per token. Keep attention,
width, depth and tokens fixed.

1, and a full-four-expert mixture that evaluates all experts. The frozen control uses a random

uses unit weights. Include a matched-combine control; hard argmax with unit weights passes
no ordinary task gradient to the router. Account for the full mixture’s extra compute.
(b)Improve the router.Explore controlled changes to the architecture. You should study these
methods in isolation and when composed with each other.
(i)Auxiliary load balancing:addλ4 ∑e fe ¯pe, wheref e is the detached assignment fraction and
¯pe the mean softmax probability. Sweep its coefficient; see Switch Transformers.
(ii)Normalized routing:apply RMSNorm to the hidden state before the router’s linear projec-
tion, keeping the experts’ inputs unchanged. This controls the scale of the routing logits.
(iii)Noisy routing:add zero-mean Gaussian noise to the routing logits during training, before
softmax and expert selection. Vary the noise scale; disable noise at evaluation.
(iv)Shared initialization:initialize all four experts with identical MLP weights, then let them
learn independently. This starts routing from experts that compute the same function.
(v)Quantile balancing:follow Jianlin Su’s derivation and Marin’s study. Route with a bias
estimated from previous steps, update it without gradients, and compute combine weights
from unbiased scores. Aggregate over the effective batch consistently.

Looping

capacity while reducing the total parameter count. A looped model achieves this by taking a single layer
and applying it multiple times sequentially instead of having unique parameters. In this problem, we
will explore what we gain or lose from utilizing looping.
